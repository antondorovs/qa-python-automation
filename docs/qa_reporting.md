# Отчёт о прогоне

После каждого запуска pytest плагин сохраняет два файла в `qa-report/`:

- `qa-summary.json` — для автоматической обработки;
- `qa-summary.md` — для просмотра человеком.

В отчёт попадают только тесты, выбранные текущей командой pytest. Например,
`-m api` создаёт сводку API-тестов. Следующий запуск перезаписывает файлы.
CI запускает основные и браузерные тесты в разных задачах и сохраняет артефакты
каждой задачи отдельно.

Контрольное правило получает статус `ready`, когда хотя бы один тест выполнен,
все выполненные тесты прошли и pytest завершился успешно. Ошибка, прерывание,
нулевое число выполненных тестов или иной ненулевой код pytest дают `blocked`.
Пропущенные тесты показаны отдельно и не входят в знаменатель процента
успешных проверок. Правило не заменяет код завершения pytest.

`tags` берутся из маркеров `api`, `contract`, `data`, `smoke`, `ui`. При ошибке
в JSON сохраняются последние 1000 символов сообщения pytest для расследования,
чтобы длинная трассировка не скрывала итоговую причину ошибки. В JSON и
Markdown есть количество тестов по маркерам; Markdown также показывает общее
время прогона, теги каждого теста и последнюю строку ошибки.
